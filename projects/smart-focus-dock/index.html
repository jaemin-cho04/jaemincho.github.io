Smart Focus Dock

A lab-tested embedded prototype that turns phone placement into a timed focus session, detects early removal, and communicates progress through direct board-level I/O.

Verified resultLab-tested state transitions, timer progression, early-removal detection, completion feedback, and reset handling on the DE10 prototype.

Context
Academic team project
Team
Three students
Prototype
Lab tested
Tools
C, DE10-Standard, ARMv7, CPUlator, memory-mapped I/O
Goal

Start a focus timer when a phone is placed on a dock and detect if it is removed early.

What we built

A DE10 prototype written in C. Board switches represented phone presence and reset; two seven-segment displays showed the current state and progress step.

Result

The lab prototype completed timed sessions, detected interruptions, displayed both outcomes, and allowed reset during active feedback sequences.

System

Four prototype states

The program read two memory-mapped inputs and used a finite-state machine to decide what the seven-segment displays should show.

HEX1 / StatePHEX0 / Progress4Focus active
  1. 01Idle

    Wait for phone input.

  2. 02Active

    Advance four timer steps.

  3. 03AComplete

    Flash C4 when time finishes.

  4. 03BInterrupted

    Flash E0 after early removal.

How it worked

Hardware access and control logic

The implementation used direct register access for board I/O and kept the state transitions separate from display formatting.

Evidence

Tested prototype versus proposed design

Tested on the DE10

  • Idle, active, complete, and interrupted transitions
  • Four visible timer-progress steps
  • Early phone-removal detection
  • Reset handling during active and flashing states

Not physically tested

The STM32 version specified an IR sensor, duration buttons, GPIO interrupts, a hardware timer, and OLED output, but it remained a code-level proposal. The DE10 prototype also used polling and blocking software delays rather than production timing.

Team context

This was a collaborative three-person ECE 3375 project. Only the DE10 prototype should be described as implemented and tested.
